📖 Resumo - Capítulo 7

🎯 CONCEITOS MAIS IMPORTANTES PARA PROVA:
  • Ciclo de Vulnerability Management: Discovery → Assessment → Prioritization → Remediation → Verification → Monitoring
  • CVSS Score: Critical (9-10), High (7-8.9), Medium (4-6.9), Low (0.1-3.9)
  • False Negative (vuln real não detectada) é MAIS GRAVE que False Positive
  • Credentialed Scan: Mais profundo (com login) | Non-credentialed: Visão de atacante externo
  • SIEM coleta e correlaciona logs | SOAR automatiza resposta a incidentes

1. Discovery
Identificar

Avaliar severidade

Priorizar por risco

Corrigir
5. Verification
Confirmar correção
6. Monitoring
Monitoramento contínuo

Tipos de Vulnerabilidades

  • Software: Bugs, falhas de código, bibliotecas vulneráveis
  • Configuration: Configurações incorretas, defaults inseguros
  • Platform: SO desatualizado, serviços desnecessários
  • Hardware: Firmware desatualizado, falhas físicas
  • Zero-Day: Vulnerabilidade desconhecida do fabricante, sem patch
  • Legacy Systems: Sistemas antigos sem suporte (EOL/EOSL)
  • Weak Encryption: Algoritmos fracos ou mal implementados
  • Race Condition: Problema de concorrência (TOC/TOU)
  • Memory Leak: Programa não libera memória, causa DoS
  • Buffer Overflow: Escreve além do buffer, execução de código

2️⃣ CVSS, CVE e NVD

ScoreSeveridade
0.0None
0.1 - 3.9Low
4.0 - 6.9Medium
7.0 - 8.9High
9.0 - 10.0Critical
  • CVE (Common Vulnerabilities and Exposures): ID único para vulnerabilidades (ex: CVE-2024-12345)
  • CWE (Common Weakness Enumeration): Categorias de fraquezas (ex: CWE-79 = XSS, CWE-89 = SQLi)
  • NVD (National Vulnerability Database): Banco de dados do governo dos EUA com CVEs e scores CVSS

3️⃣ Vulnerability Scanning

🔑 Credentialed

  • Com credenciais de login
  • Mais profundo (acessa configurações internas)
  • Menos falsos negativos

👁️ Non-credentialed

  • Sem credenciais
  • Visão de atacante externo
  • Mais falsos negativos

Ferramentas de Scan

  • Nessus: Comercial, mais usado, interface gráfica (Tenable)
  • OpenVAS: Open source, alternativa gratuita ao Nessus (Greenbone)
  • Qualys: Cloud-based, monitoramento contínuo
  • Rapid7 Nexpose: Comercial, integra com Metasploit
  • Tenable.io: Versão cloud do Nessus

Interpretação de Resultados

TipoDescrição
True PositiveVulnerabilidade real detectada corretamente ✅
False PositiveAlerta incorreto (não é vulnerabilidade) ⚠️
False NegativeVulnerabilidade real NÃO detectada ❌ (MAIS GRAVE!)
True NegativeCorretamente não alerta (sistema seguro) ✅
⚠️ REGRA DE OURO: False Negative é MUITO pior que False Positive! Deixar uma vulnerabilidade real sem detecção pode levar a um ataque real.

4️⃣ SIEM, SOAR e DLP

📊 SIEM

Security Information and Event Management

  • Coleta e agrega logs
  • Correlaciona eventos
  • Gera alertas e dashboards
  • Ex: Splunk, QRadar, ArcSight

🤖 SOAR

Security Orchestration, Automation and Response

  • Automatiza resposta a incidentes
  • Playbooks automáticos
  • Integra ferramentas
  • Ex: Cortex XSOAR, Phantom

🔒 DLP

Data Loss Prevention

  • Network DLP (tráfego)
  • Endpoint DLP (USB, impressão)
  • Storage DLP (dados em repouso)
  • Cloud DLP (SaaS)

NetFlow

  • Protocolo Cisco para coleta de metadados de tráfego
  • Informações: IPs origem/destino, portas, protocolo, bytes, pacotes
  • NÃO captura: Payload dos pacotes
  • Uso: Análise de tráfego, detecção de anomalias, capacity planning

5️⃣ Penetration Testing

Tipos de Conhecimento

  • Black Box: Sem conhecimento prévio. Simula atacante externo.
  • White Box: Conhecimento completo (código, arquitetura, credenciais). Mais profundo.
  • Gray Box: Conhecimento parcial. Simula atacante com algum acesso.

Fases do Pentest

  1. Planning: Escopo, regras de engajamento, objetivos
  2. Reconnaissance: Coleta de informações
  3. Scanning: Port scan, vulnerability scan
  4. Exploitation: Explorar vulnerabilidades, ganhar acesso
  5. Post-Exploitation: Manter acesso, privilege escalation, lateral movement
  6. Reporting: Documentar achados, recomendações

Ferramentas de Pentest

Metasploit: Framework de exploração
Burp Suite: Proxy para web apps
OWASP ZAP: Web scanner open source
Nmap: Port scanning
sqlmap: SQL injection automation
Mimikatz: Windows credential dumping
SET: Social Engineer Toolkit
Aircrack-ng: Wi-Fi security

Regras de Engajamento (ROE)

  • Documento assinado antes do pentest (proteção legal)
  • Define: Escopo (IPs, domínios), fora de escopo, horários, métodos permitidos, contatos de emergência
💡 DIFERENÇAS IMPORTANTES:
  • Vulnerability Scan vs Pentest: Scan é automatizado, identifica mas não explora. Pentest é manual, explora e simula atacante real.
  • Pentest vs Red Team: Pentest tem escopo definido, objetivo é encontrar vulnerabilidades. Red Team tem objetivo específico (ex: acessar servidor X), testa a defesa (Blue Team), mais stealth.

6️⃣ Remediação e Opções

OpçãoDescrição
PatchAplicar correção oficial do fabricante
WorkaroundSolução temporária até o patch
MitigationReduzir risco sem eliminar (ex: regra de firewall, WAF)
AcceptAceitar o risco formalmente (baixo impacto, alto custo de correção)
ExceptionAceitar temporariamente com justificativa

EOL / EOSL

  • End of Life / End of Service Life: Software/hardware sem suporte do fabricante
  • Riscos: Sem patches de segurança, vulnerabilidades não corrigidas, não conformidade
  • Opções: Upgrade, substituir, isolar, aceitar risco
