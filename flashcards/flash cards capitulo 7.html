📖 Resumo - Capítulo 7

🎯 CONCEITOS MAIS IMPORTANTES PARA PROVA:
  • Ciclo de Vulnerability Management: Discovery → Assessment → Prioritization → Remediation → Verification → Monitoring
  • CVSS Score: Critical (9-10), High (7-8.9), Medium (4-6.9), Low (0.1-3.9)
  • False Negative (vuln real não detectada) é MAIS GRAVE que False Positive
  • Credentialed Scan: Mais profundo (com login) | Non-credentialed: Visão de atacante externo
  • SIEM coleta e correlaciona logs | SOAR automatiza resposta a incidentes

1️⃣ Ciclo de Gestão de Vulnerabilidades

1. Discovery
Identificar ativos e vulnerabilidades
2. Assessment
Avaliar severidade e impacto
3. Prioritization
Priorizar por risco (CVSS + contexto)
4. Remediation
Aplicar patches, workarounds, mitigações
5. Verification
Verificar se a correção foi efetiva
6. Monitoring
Monitorar continuamente novas ameaças

Tipos de Vulnerabilidades

  • Software: Bugs, falhas de código, bibliotecas vulneráveis
  • Configuration: Configurações incorretas, defaults inseguros (ex: senhas padrão)
  • Platform: SO desatualizado, serviços desnecessários rodando
  • Hardware: Firmware desatualizado, falhas físicas (ex: Meltdown/Spectre)
  • Zero-Day: Vulnerabilidade desconhecida do fabricante, sem patch disponível
  • Legacy Systems: Sistemas antigos sem suporte (EOL/EOSL)
  • Weak Encryption: Algoritmos fracos (MD5, SHA-1, RC4) ou mal implementados

2️⃣ CVSS, CVE e NVD

ScoreSeveridade
0.0None
0.1 - 3.9Low (baixo)
4.0 - 6.9Medium (médio)
7.0 - 8.9High (alto)
9.0 - 10.0Critical (crítico)
  • CVE (Common Vulnerabilities and Exposures): ID único para vulnerabilidades (ex: CVE-2024-12345). Mantido pela MITRE.
  • CWE (Common Weakness Enumeration): Catálogo de categorias de fraquezas (ex: CWE-79 = XSS, CWE-89 = SQL Injection)
  • NVD (National Vulnerability Database): Banco de dados do governo dos EUA que contém todas as CVEs publicadas, com scores CVSS, informações de impacto e referências.

3️⃣ Vulnerability Scanning

🔑 Credentialed Scan

  • Usa credenciais de acesso (login)
  • Consegue inspecionar configurações internas
  • Mais profundo e preciso
  • Menos falsos negativos

👁️ Non-credentialed Scan

  • Sem credenciais
  • Visão de atacante externo
  • Mais limitado, apenas o que está exposto
  • Mais falsos negativos

Ferramentas de Scan

  • Nessus: Scanner comercial da Tenable. É o mais utilizado no mercado. Interface gráfica amigável, vasta base de plugins.
  • OpenVAS: Scanner de vulnerabilidades open source (atualmente Greenbone). Alternativa gratuita ao Nessus.
  • Qualys: Plataforma cloud-based de gerenciamento de vulnerabilidades. Monitoramento contínuo.
  • Rapid7 Nexpose: Scanner comercial que integra nativamente com o Metasploit, permitindo validação por exploração.
  • Tenable.io: Versão cloud do Nessus.

Interpretação de Resultados

TipoDescrição
True PositiveVulnerabilidade real detectada corretamente ✅
False PositiveAlerta incorreto (não é vulnerabilidade) ⚠️
False NegativeVulnerabilidade real NÃO detectada ❌ (MAIS GRAVE!)
True NegativeCorretamente não alerta (sistema seguro) ✅
⚠️ REGRA DE OURO: False Negative é MUITO pior que False Positive! Deixar uma vulnerabilidade real sem detecção pode levar a um ataque real.

4️⃣ SIEM, SOAR e DLP

📊 SIEM

Security Information and Event Management

  • Coleta e agrega logs de múltiplas fontes
  • Correlaciona eventos em tempo real
  • Gera alertas e dashboards
  • Ex: Splunk, IBM QRadar, ArcSight

🤖 SOAR

Security Orchestration, Automation and Response

  • Automatiza resposta a incidentes
  • Playbooks automáticos (workflows)
  • Integra ferramentas de segurança
  • Ex: Palo Alto Cortex XSOAR, Splunk Phantom

🔒 DLP

Data Loss Prevention

  • Network DLP: monitora tráfego de rede
  • Endpoint DLP: monitora USB, impressão, clipboard
  • Storage DLP: dados em repouso
  • Cloud DLP: SaaS (O365, Google Workspace)

NetFlow

  • Protocolo da Cisco para coleta de metadados de tráfego
  • Informações coletadas: IPs origem/destino, portas, protocolo, bytes, pacotes, timestamps
  • NÃO captura: Payload dos pacotes (apenas metadados)
  • Uso: Análise de tráfego, detecção de anomalias, capacity planning, investigação de incidentes

5️⃣ Penetration Testing

Tipos de Conhecimento (Knowledge Types)

  • Black Box: Sem conhecimento prévio do alvo. Simula um atacante externo. Mais realista, porém menos profundo.
  • White Box: Conhecimento completo (código fonte, diagramas de arquitetura, credenciais). Mais profundo e eficiente.
  • Gray Box: Conhecimento parcial. Simula um atacante com algum nível de acesso (ex: funcionário, fornecedor).

Fases do Pentest

  1. Planning: Definição de escopo, regras de engajamento (ROE), objetivos
  2. Reconnaissance: Coleta de informações (OSINT, redes sociais, DNS)
  3. Scanning: Port scan, vulnerability scan, enumeração de serviços
  4. Exploitation: Explorar vulnerabilidades encontradas, tentar ganhar acesso
  5. Post-Exploitation: Manter acesso, privilege escalation, lateral movement, exfiltração
  6. Reporting: Documentar achados, evidências, impacto e recomendações de remediação

Ferramentas de Pentest

Metasploit: Framework de exploração, módulos de exploit e payload
Burp Suite: Proxy interceptador para testes em aplicações web
OWASP ZAP: Web scanner open source, alternativa ao Burp
Nmap: Port scanning e descoberta de rede
sqlmap: Automação de SQL injection
Mimikatz: Extração de credenciais do Windows
SET (Social Engineer Toolkit): Automação de engenharia social e phishing
Aircrack-ng: Teste de segurança Wi-Fi

Regras de Engajamento (ROE)

  • Documento formal assinado antes do pentest (proteção legal)
  • Define: Escopo (IPs, domínios, aplicações), fora de escopo, horários permitidos, métodos autorizados, contatos de emergência
  • Inclui plano de comunicação e procedimentos em caso de descoberta de dados críticos
💡 DIFERENÇAS IMPORTANTES:
  • Vulnerability Scan vs Pentest: Scan é automatizado, identifica vulnerabilidades conhecidas mas não explora. Pentest é manual, explora vulnerabilidades para validar se são realmente exploráveis.
  • Pentest vs Red Team: Pentest tem escopo definido, objetivo é encontrar o máximo de vulnerabilidades. Red Team tem objetivo específico (ex: acessar um ativo crítico), opera de forma stealth, testa a capacidade de detecção da defesa (Blue Team).

6️⃣ Remediação e Opções

OpçãoDescrição
PatchAplicar correção oficial do fabricante (a melhor opção quando disponível)
WorkaroundSolução temporária até que o patch oficial seja aplicado (ex: desabilitar funcionalidade vulnerável)
MitigationReduzir o risco sem eliminar a vulnerabilidade (ex: regra de firewall, WAF, segmentação)
AcceptAceitar o risco formalmente (baixo impacto, alto custo de correção, necessidade de aprovação da gestão)
ExceptionAceitar temporariamente com justificativa, renovável periodicamente

EOL / EOSL (End of Life / End of Service Life)

  • Indica que um produto (software/hardware) não recebe mais suporte do fabricante
  • Riscos: Sem patches de segurança, vulnerabilidades não corrigidas, não conformidade com regulamentações
  • Opções: Upgrade para versão suportada, substituir, isolar na rede (segmentação), ou aceitar o risco (com seguro cibernético)
