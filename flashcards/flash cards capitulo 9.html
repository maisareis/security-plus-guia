📖 Resumo - Capítulo 9

🎯 CONCEITOS MAIS IMPORTANTES PARA PROVA:
  • 6 fases do Incident Response: Preparation → Identification → Containment → Eradication → Recovery → Lessons Learned
  • Ordem de Volatilidade: CPU/RAM (mais volátil) → Disco → Logs → Backups (menos volátil)
  • Chain of Custody: Documentar tudo para admissibilidade legal
  • 3-2-1 Rule: 3 cópias, 2 mídias, 1 offsite
  • RPO vs RTO: RPO = quanto dado perder, RTO = tempo de recuperação

1️⃣ Processo de Resposta a Incidentes

1. PreparationPlanos, ferramentas
2. IdentificationDetectar
3. ContainmentIsolar
4. EradicationRemover causa
5. RecoveryRestaurar
6. Lessons LearnedMelhorias

Containment (Contenção)

  • Isolation: Desconectar sistema da rede para prevenir propagação, mas mantendo evidências.
  • Segmentation: Mover sistema para uma VLAN isolada (quarentena).
  • Removal: Desligar sistema (último caso, pois perde dados voláteis).

Eradication e Recovery

  • Eradication: Remover causa raiz: deletar malware, fechar vulnerabilidade, revogar credenciais comprometidas.
  • Recovery: Restaurar sistemas à operação normal: restore de backup, rebuild, aplicar patches, monitorar.

2️⃣ Log Management

  • SIEM: Coleta, agrega e correlaciona logs de múltiplas fontes para detecção de ameaças.
  • Retention: Armazenar logs conforme requisitos de compliance (ex: 1 ano).
  • ELK Stack: Elasticsearch (busca), Logstash (coleta/processamento), Kibana (visualização). Solução open source de log management.

3️⃣ Digital Forensics

Ordem de Volatilidade (coletar do mais volátil para o menos volátil)

  1. CPU registers, cache - extremamente volátil
  2. RAM (memória volátil) - se desligar, perde
  3. Swap/Page file - memória virtual
  4. Disco rígido - persistente
  5. Logs remotos - armazenados em outro sistema
  6. Backups - menos volátil

Chain of Custody (Cadeia de Custódia)

  • Documentar quem teve acesso à evidência, quando, onde e por quê.
  • Essencial para admissibilidade da evidência em tribunal.
  • Cada transferência deve ser registrada.

Ferramentas Forenses

FerramentaUso
FTK ImagerCriar imagens forenses (E01, raw). GUI, Windows.
dd/dcflddDisk imaging no Linux. Bit-by-bit copy. dcfldd tem hash integrado.
AutopsyAnálise forense GUI. Timeline, file recovery, keyword search.
VolatilityMemory forensics. Analisa RAM dumps (processos, conexões, malware).
WiresharkNetwork forensics. Análise de PCAPs.
NetworkMinerNetwork forensics passiva. Extrai arquivos e credenciais de PCAPs.
⚠️ REGRAS DE OURO DA FORENSE:
  • Write Blocker: Usar hardware ou software para prevenir modificação da evidência durante análise.
  • Hash da Evidência: Calcular hash (MD5/SHA-256) antes e depois da análise para provar integridade.
  • Live Acquisition: Capturar RAM enquanto sistema está ligado (dados voláteis).
  • Dead Acquisition: Imaging de disco desligado.

4️⃣ Redundância

RAID (Redundant Array of Independent Disks)

RAID 0

Striping. Performance, SEM REDUNDÂNCIA

RAID 1

Mirroring. 50% capacidade, tolera 1 falha

RAID 5

Striping + parity. Mínimo 3 discos, tolera 1 falha

RAID 6

Double parity. Mínimo 4 discos, tolera 2 falhas

RAID 10

Mirror de stripes. Performance + redundância

Alta Disponibilidade

  • Clustering: Múltiplos servidores atuando como um. Active-active ou active-passive. Failover automático.
  • Load Balancing: Distribui tráfego entre servidores (round-robin, least connections). Aumenta performance e disponibilidade.
  • Failover: Troca automática para servidor/componente de backup quando o primário falha.

5️⃣ Backup

Tipos de Backup

TipoDescriçãoRestore
FullCópia completaRápido
IncrementalMudanças desde último backupLento (full + todos incrementais)
DifferentialMudanças desde último fullMédio (full + último differential)

Conceitos Importantes

  • 3-2-1 Rule: 3 cópias, 2 mídias, 1 offsite
  • RPO (Recovery Point Objective): Quanto dado pode perder
  • RTO (Recovery Time Objective): Tempo para recuperar
  • MTBF (Mean Time Between Failures): Confiabilidade
  • MTTR (Mean Time To Repair): Tempo médio para reparo

DR Sites

  • Hot Site: Totalmente equipado, failover imediato (RTO minutos)
  • Warm Site: Equipado mas sem dados atuais (RTO horas)
  • Cold Site: Apenas espaço físico (RTO dias)

Backup Moderno

  • Immutable Backup: Backup que não pode ser modificado/deletado (WORM). Protege contra ransomware.
  • Air Gap Backup: Backup fisicamente desconectado da rede.
  • Snapshot: Estado de VM/storage em momento. Rápido mas NÃO é backup.
  • Replication: Cópia contínua para outro local (síncrona/assíncrona).
